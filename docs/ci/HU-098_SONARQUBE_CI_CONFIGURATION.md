# HU-098 SonarQube CI Configuration

## Purpose

This document explains the backend CI/CD pipeline failure related to SonarQube and the safe configuration applied in HU-098.

## Failure Summary

After HU-097 was merged into `develop`, the backend pipeline confirmed that Maven build, tests, and test result publishing were working. The remaining failure happened only in the `SonarQube Analysis` step.

The pipeline error was:

```text
SonarQube server [] can not be reached
Expected URL scheme 'http' or 'https' but no colon was found
```

## Root Cause

The workflow executed `mvn sonar:sonar` with an empty or invalid `SONAR_HOST_URL`.

This means the SonarQube host was not configured in GitHub repository variables or secrets, or it did not include a valid URL scheme.

## Required Configuration

To enable SonarQube analysis, configure:

| Name | Recommended location | Required | Example |
| --- | --- | --- | --- |
| `SONAR_HOST_URL` | Repository variable or repository secret | Yes, when Sonar is enabled | `https://sonarcloud.io` or `http://your-host:9000` |
| `SONAR_TOKEN` | Repository secret | Yes, when Sonar is enabled | Token generated by SonarQube or SonarCloud |

The workflow first checks `vars.SONAR_HOST_URL` and then falls back to `secrets.SONAR_HOST_URL`.

## URL Format

`SONAR_HOST_URL` must start with one of these schemes:

```text
https://
http://
```

Valid examples:

```text
https://sonarcloud.io
http://localhost:9000
http://sonarqube.example.com:9000
```

Invalid examples:

```text
sonarcloud.io
localhost:9000
sonarqube.example.com
```

## CI Behavior

SonarQube is currently conditional:

- If `SONAR_TOKEN` or `SONAR_HOST_URL` is missing, the workflow skips SonarQube and continues.
- If `SONAR_HOST_URL` does not start with `http://` or `https://`, the workflow skips SonarQube and continues.
- If both values are configured and the URL format is valid, SonarQube analysis runs normally.
- If SonarQube is configured but the server is unreachable or the quality gate fails, the pipeline can fail as expected.

This prevents an unconfigured optional quality tool from blocking Maven build and tests.

## Relation With HU-097

HU-097 fixed backend test failures:

- Maven build passed.
- Unit and context tests passed.
- Test result publishing passed.

HU-098 does not change tests or production code. It only addresses the remaining CI configuration failure in the SonarQube step.

## Validation

1. GitHub Actions workflow syntax remains valid.
2. Maven build still runs.
3. Tests still run on pushes.
4. SonarQube does not fail the pipeline when missing configuration.
5. No secrets are committed to the repository.
